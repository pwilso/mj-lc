Error when compiling changed Cython files for the first time through Sentaurus.¶

Message:

The first time you run the program (or if you changed anything in the Cython files) it may throw some warnings which are ignored when running in the terminal but cause Sentaurus to exit with an error.

The error will look like a compiler error (something with “gcc” in the error message).

Solution:

pip3 install Cython
cythonize path/to/Python/tmm/tmm_core_mw.pyx

This ensures that tmm_core_mw.pyx has been properly updated/compiled.

Next, open a python terminal.

import os
import sys
sys.path.append(os.path.join(os.path.dirname(os.path.abspath(file)), '..', 'Python')) # may need to adjust depending on your cwd
sys.path.append(os.path.join(os.path.dirname(os.path.abspath(file)), '..', 'Python', 'tmm'))
import pyximport; pyximport.install()
import epi_cmd_LC
import tmm.tmm_core_mw as tmm

You’ll recognize this as just the first block of the LCMatrix.py script. Running through a Python terminal first allows messages generated by the compiler to be ignored. Subsequent runs will not generated these messages allowing the Sentaurus program to proceed.

Error when trying to run a LCMatrix.py file that previously compiled fine.¶

Message:

epi_cmd_LC.c:1:2: error: #error Do not use this file, it is the result of a failed Cython compilation.
#error Do not use this file, it is the result of a failed Cython compilation.

DistutilsExecError: command 'gcc' failed with exit status 1

CompileError: command 'gcc' failed with exit status 1

ImportError: Building module epi_cmd_LC failed: ["distutils.errors.CompileError: command 'gcc' failed with exit status 1\n"]

Solution:

If running cythonize on epi_cmd_LC.pyx does not generate any messages then attempt to “wake-up” the compiler by adding a small change to the beginning of the file.

For example, add the variable test_change = 1 at the beginning of the file.

Rerun cythonize on the .pyx file. It will hopefully generate outputs and recompile the file fully now.

Troubleshooting tricky Python packages¶

Message:

Sometimes you may need to install a package separately from your usual Python environment. This could be due to compatibility issues with Sentaurus for example. In these cases it is possible to install a version of the module you need locally and then call it from within the Python script. Below is an example of how this is done for a Python module called “feather” which was installed using conda.

Solution:

import importlib
spec = importlib.util.spec_from_file_location("module", "/path/to/module/miniconda3/pkgs/feather-format-0.4.1-pyh9f0ad1d_0/site-packages/feather/__init__.py")
feather = importlib.util.module_from_spec(spec)

Other Cython and Compiler Errors¶

Message:

The cythonize commands fail with the following error:

AttributeError: 'PropertyScope' object has no attribute 'namespace_cname'

Solution:

This signals that two objects have the same name. For example, this was generated from within the epilayer class where both a variable public nk and a function nk(self, double wl) and was resolved by removing the nk variable which was not used. Avoid naming functions after imported modules and variables. Avoid installing python modules with the same names as custom Python scripts and modules used in the project (for example, it is possible to pip install both a tmm package and a tdr package, which have names common with custom modules used in the project.)

Message:

The cythonize commands run successfully from the terminal but the pyximport commands in Python generate a compiler error:

ImportError: Building module epi_cmd_LC failed:['distutils.error.CompileError: command 'depot/qsc/QSCU/GCC/bin/gcc' failed with exit status 1\n"]

The gcc path does not exist. The user should find the gcc folder that exists on their system and set the variable prior to running the program.

export CC=/usr/bin/gcc
